## コンテナーの初期化，begin(x)/end(x)，auto，レンジベースループ
```cpp
#include "stdafx.h"
#include <array>
#include <iostream>
#ifdef _UNICODE
#define _tcout	(std::wcout)
#else
#define _tcout	(std::cout)
#endif

int _tmain(int argc, _TCHAR* argv[])
{
    // コンテナーの初期化が簡単にできるようになった
    std::array<double,5>	doubles = {0.1,0.5,0.4,0.2,0.3};

    // std::begin, std::endが使えるようになった
    std::sort(std::begin(doubles), std::end(doubles));

    // auto宣言により，型の自動判別をしてくれるようになった（この場合，イテレーターではなく実体）
    // すべての要素に順次アクセスする場合には，レンジペースループを使用できるようになった
    for (auto data : doubles) {
        _tcout << data << _T(" ");
    }

    // コンテナーに変更を伴わない場合には const auto&
    for (const auto& data : doubles) {
        _tcout << data << _T(" ");
    }
    // コンテナーの変更を伴う場合には auto&&
    // 型推論では，右辺値は右辺値，左辺値は左辺値との解釈がされるため（つまり，autoを使うときにのみ）
    for (auto&& data : doubles) {
        _tcout << data << _T(" ");
    }

    return 0;
}
```

## 型サポート
`decltype(arg)`により，コンパイラーに型を類推させることができる．  
第一条件 : `decltype(arg)`にて，argがローカルスコープ or 名前空間スコープの変数 or 静的メンバー変数 or 関数パラメーターを参照している場合，結果はその変数またはパラメーターの宣言された型になる．   
```cpp
int integerType;
decltype(integerType)  integerType2;   // type is int
```
第二条件 : `decltype(arg)`にて，上記以外の場合，argがlvalueのときの結果は`T&`，argがxvalueのときの結果は`T&&`，argがprvalueのとき結果は`T`である． lvalue/prvalue/xvalueについては，https://ja.cppreference.com/w/cpp/language/value_category に詳しい． 
```cpp
struct Hoge {
int hoge
void type {decltype(this) hoge_;}  // type is Hoge (prvalue)
};
const Hoge* pHoge = new Hoge();
decltype(pHoge->hoge)   hoge1; // type is int (prvalue???)
decltype((pHoge->hoge)) hoge2; // type is int& (lvalue)
```
ただし，次の場合にはまだ宣言されていない変数を使用しているため，decltypeを使用することはできないが，型を後置することにより回避できる． 
```cpp
template<typename type1, typename type2> decltype(_t1_+_t2_) AddingFunc(type1 _t1_, type2 _t2_) {return _t1_+_t2_;}
template<typename type1, typename type2> AddingFunc(type1 _t1_, type2 _t2_) -> decltype(_t1_+_t2_) {return _t1_+_t2_;}
```

### remove_reference/remove_const/remove_pointer
```cpp
const int* pHoge;
decltype(*pHoge) pHoge_;   // type is const int&
```
上記における&とconstを除去することを考える．  
&を除去するにはstd::remove_reference<>を用いる．  
constを除去するにはstd::remove_const<>を用いる．  
*を除去するにはstd::remove_pointer<>を用いる．  
```cpp
const int* pHoge;
decltype(*pHoge) pHoge1; // type is const int& (第二条件 lvalue)
std::remove_reference<decltype(*pHoge)>::type pHoge2; // type is const int
std::remove_const<decltype(*pHoge)>::type pHoge3; // type is int&
std::remove_pointer<decltype(pHoge)>::type pHoge4; // type is const int (第一条件)
```

### invoke_result
```cpp
#include <type_traits>

int fuga(long&, double*) {return 0;}

class CHoge
{
public:
    int fuga(long*, double&) const {return 0;};
    int operator()(short*, float&) {return 0;};
};

int main()
{
    static_assert(std::is_same<int, std::invoke_result<decltype(&CHoge::fuga), CHoge, long*, double&>::type>::value);
    static_assert(std::is_same<int, std::invoke_result<decltype(fuga), long&, double*>::type>::value);
    static_assert(std::is_same<int, std::invoke_result<CHoge, short*, float&>::type>::value);
}
```

### unique_ptr
スコープスマートポインタ．所有権があるポインタが破棄される時に破棄される．
`auto_ptr`の代わりに使用できる． 
```cpp
void test_unique_ptr()
{
    // 他で取得したメモリーを代入できる
    CHoge*  pHoge01_tmp = new CHoge(1);
    std::unique_ptr<CHoge>  pHoge01(pHoge01_tmp);
    // resetを用いても代入できる
    std::unique_ptr<CHoge>  pHoge02 = nullptr;
    pHoge02.reset(new CHoge(2));
    // もちろん直接的にも
    std::unique_ptr<CHoge>  pHoge03(new CHoge(3));

//  std::unique_ptr<CHoge>  pHoge04 = pHoge03;  // 他にはコピーできない
//  std::unique_ptr<CHoge>  pHoge04(pHoge03);   // 他にはコピーできない
//  std::shared_ptr<CHoge>  pHoge04(pHoge03);   // 他にはコピーできない
//  std::weak_ptr<CHoge>    pHoge04(pHoge03);   // 他にはコピーできない
    std::unique_ptr<CHoge>  pHoge04 = nullptr;
    pHoge04.swap(pHoge03);  // swapはできる（所有権はpHoge03からpHoge04へ移行）
    pHoge03 = std::move(pHoge04);   // ムーブはできる（所有権はpHoge04からpHoge03へ移行）
    std::shared_ptr<CHoge>  pHoge05 = std::move(pHoge03);   // shared_ptrへムーブはできる（詳細はshared_ptrへ）

    CHoge*  pHoge02_tmp = pHoge02.get();    // 中身を参照するだけで，取得したメモリーは自身で解放してはならない
    CHoge*  pHoge03_tmp = pHoge03.release();    // 管理から解放する(release)ので，取得したメモリーは自身で解放しなければならない
    // でもshared_ptrへ移行したので，ここでは空

    if (pHoge01_tmp) pHoge01_tmp->print();
    if (pHoge02_tmp) pHoge02_tmp->print();
    if (pHoge03_tmp) pHoge03_tmp->print();
    if (pHoge01) pHoge01->print();
    if (pHoge02) pHoge02->print();
    if (pHoge03) pHoge03->print();  //releaseしたので呼び出されない
    if (pHoge04) pHoge04->print();  //moveしたので呼び出されない

    // uniquw_ptrでは配列は通常通り使える
    std::unique_ptr<CHoge[]>    pHoge06(new CHoge[3]);
    for (int cnt = 0; cnt < 3; cnt++) {
        pHoge06[cnt].print();
    }

    pHoge02.reset();    // 引数なしのresetで解放させることもできる

    // 解放関数が指定されている場合には，deleterでそれを指定することもできる
    struct hoge_deleter{
        void operator()(CHoge* ptr_){
            std::wcout << _T("hoge_deleter") << std::endl;
            ptr_->print();
            delete ptr_;
        }
    };
    std::unique_ptr<CHoge, hoge_deleter>    pHoge07(new CHoge(7));
}
```

### shared_ptr
参照カウンターつきスマートポインタ．参照カウントが0になったときに破棄される． 
```cpp
void test_shared_ptr()
{
    // 直接的に生成
    std::shared_ptr<CHoge>  pHoge01(new CHoge(1));
    // unique_ptrからmove
    std::unique_ptr<CHoge>  pHoge02_unq(new CHoge(2));
    std::shared_ptr<CHoge>  pHoge02 = std::move(pHoge02_unq);
    // shared_ptrからshared_ptrへ代入
    std::shared_ptr<CHoge>  pHoge03 = pHoge02;
    // resetを用いても代入できる
    std::shared_ptr<CHoge>  pHoge04 = nullptr;
    pHoge04.reset(new CHoge(4));
    // 通常はmake_sharedを使用すべき
    std::shared_ptr<CHoge>  pHoge05 = std::make_shared<CHoge>(5);
    // shared_ptrを生成するにあたって，make_sharedはオブジェクトホルダーとカスタムデリーター用メモリ領域を連続領域で確保してくれるようで，効率が良い

    std::wcout << _T("pHoge01 used ") << pHoge01.use_count() << std::endl;  // 一箇所
    std::wcout << _T("pHoge02 used ") << pHoge02.use_count() << std::endl;  // 二箇所
    std::wcout << _T("pHoge03 used ") << pHoge03.use_count() << std::endl;  // 二箇所
    std::wcout << _T("pHoge04 used ") << pHoge04.use_count() << std::endl;  // 一箇所
    std::wcout << _T("pHoge05 used ") << pHoge05.use_count() << std::endl;  // 一箇所

    CHoge*  pHoge01_tmp = pHoge01.get();    // 中身を参照するだけで，取得したメモリーは自身で解放してはならない
    // unique_ptrのようなreleaseはない

    if (pHoge01) pHoge01->print();
    if (pHoge02) pHoge02->print();
    if (pHoge03) pHoge03->print();
    if (pHoge04) pHoge04->print();
    if (pHoge05) pHoge05->print();

    // shared_ptrでは配列は，deleterを明示的に指定する必要がある
    // また配列の宣言で，make_sharedは使えない
    std::shared_ptr<CHoge>  pHoge06(new CHoge[3], std::default_delete<CHoge[]>());
    for (int cnt = 0; cnt < 3; cnt++) {
        pHoge06.get()[cnt].print();
    }
}
```

### weak_ptr
```cpp
void test_weak_ptr()
{
    // weak_ptrはそれ自身では生成できず，shared_ptrを受け取ることで生きてくる
    std::shared_ptr<CHoge>  pHoge01_shared01 = std::make_shared<CHoge>(1);
    std::weak_ptr<CHoge>    pHoge01 = pHoge01_shared01;
    std::wcout << _T("pHoge01 used ") << pHoge01.use_count() << std::endl;  // 一箇所

    std::weak_ptr<CHoge>    pHoge02;
    {
        // shared_ptrがスコープを抜ければ，shared_ptrは自動的に所有権を手放す
        std::shared_ptr<CHoge>  pHoge01_shared02 = pHoge01.lock();
        std::wcout << _T("pHoge01 used ") << pHoge01.use_count() << std::endl;  // 二箇所
        // あくまで管理者はshared_ptr
        std::shared_ptr<CHoge>  pHoge02_shared01 = std::make_shared<CHoge>(2);
        pHoge02 = pHoge02_shared01;
    }
    // スコープを抜けると，shared_ptrがdeleteする
    std::wcout << _T("pHoge02 used ") << pHoge02.use_count() << std::endl;  // 零箇所
    _ASSERT(pHoge02.expired());

    if (pHoge01.expired() == false) {
        // weak_ptrは直接関数は呼び出せないので，lockを使ってshared_ptrを取得して使う
        std::shared_ptr<CHoge>  pHoge01_shared03 = pHoge01.lock();
        pHoge01_shared03->print();
        std::wcout << _T("pHoge01 used ") << pHoge01.use_count() << std::endl;  // 二箇所
    }
}
```

### 循環参照
`weak_ptr`の使い所としてあげられるのが，循環参照の場合である． 
```cpp
weak_ptrの使い所としてあげられるのが，循環参照の場合である．

class CCycloHoge0
{
public:
    // m_pCycloHogeは他で所有しているとして，ここでは廃棄しない
    virtual ~CCycloHoge0() {std::wcout<<_T("used ")<<m_pCycloHoge.use_count()<<std::endl;};
public:
    std::shared_ptr<CCycloHoge0>    m_pCycloHoge;
};

void test_cycle0()
{
    std::shared_ptr<CCycloHoge0>    pCycloHoge1 = std::make_shared<CCycloHoge0>();
    std::shared_ptr<CCycloHoge0>    pCycloHoge2 = std::make_shared<CCycloHoge0>();

    pCycloHoge1->m_pCycloHoge = pCycloHoge2;
    pCycloHoge2->m_pCycloHoge = pCycloHoge1;
    _ASSERT(pCycloHoge1.use_count()==2);
    _ASSERT(pCycloHoge2.use_count()==2);

    // この方法ではうまくいかない．なぜなら，
    // pCycloHoge1のデストラクターが呼ばれるときに，pCycloHoge1の所有権を一つ放棄する
    // pCycloHoge2のデストラクターが呼ばれるときに，pCycloHoge2の所有権を一つ放棄する
    // 互いに保持しているm_pCycloHogeの解放のタイミングがない
    // もしCCycloHoge0のデストラクターで解放したら，それは二重開放になってしまう
}

class CCycloHoge1
{
public:
    virtual ~CCycloHoge1() {std::wcout<<_("used ")<<m_pCycloHoge.use_count()<<std::endl;};
public:
    std::weak_ptr<CCycloHoge1>  m_pCycloHoge;
};

void test_cycle1()
{
    std::shared_ptr<CCycloHoge1>    pCycloHoge1 = std::make_shared<CCycloHoge1>();
    std::shared_ptr<CCycloHoge1>    pCycloHoge2 = std::make_shared<CCycloHoge1>();

    pCycloHoge1->m_pCycloHoge = pCycloHoge2;
    pCycloHoge2->m_pCycloHoge = pCycloHoge1;
    _ASSERT(pCycloHoge1.use_count()==1);
    _ASSERT(pCycloHoge2.use_count()==1);

    // weak_ptrを使うことで解決できる．なぜなら，shared_ptrの使用数はお互い自身の使用数の"1"だからである．
}
```

## lambda
```
[](){}();
[]  // ラムダキャプチャー（lambda-capture）
()  // 引数宣言項（parameter-declaration-clause）
{}  // 実行文（compound-statement）
()  // 関数呼び出し式（Function call expression）
```

### 引数宣言項（parameter-declaration-clause）
通常の関数と同様に引数の宣言を行う．  
省略可．   
### 関数呼び出し式（Function call expression）
通常の関数と同様に呼び出しに引数を与える．  
引数宣言項が省略可なら省略可．   
### 実行文（compound-statement）
通常の関数と同様に実行すべき内容を与える．
```cpp
std::function<void()>   func2 = []{std::_tcout << _T("Hello,World") << std::endl;};
func2();
```
### 戻り値
->による後置指定が行える． 
```cpp
// autoを使いながらも，戻り値を明示的に書くことができる
auto    func3 = []()->int{return 'a';};
std::_tcout << func3();
```
### ラムダキャプチャー（lambda-capture）
ここでの指定により，ラムダ外にある変数を使用することができる．    
```
[]      // ラムダ関数外変数は使うことができない．
[&]     // すべてのラムダ外変数は使用する際に参照渡しされる．
[=]     // すべてのラムダ外変数は使用する際にコピーされる．
```
変数別の指定も可能である．
```
[x,&y]  // xはコピーされ，yは参照渡しされる．
[&,x]   // xはコピーされ，その他は参照渡しされる．
[=,&y]  // yは参照渡しされ，その他はコピーされる．
```
```cpp
    int int4 = 10;
//  auto    func4 = [=](int int0){int4 += int0;};   // コピーされた変数はラムダの仕様によりconst定義されている
    auto    func5 = [=](int int0) mutable {int4 += int0;};  // mutableにより回避できる
    auto    func6 = [&](int int0){int4 += int0;};   // 参照渡しは問題ない
    func5(10);  // これではint4の値に変化はない
    func6(10);  // int4に+10される
```

## 右辺値参照
型名に&&を付ける事で右辺値参照でオブジェクトを受け取ることができる．  
ただし，受け取れるオブジェクトは，一時的なオブジェクトのみである．  
```cpp
int& rHoge = 10; // NG
int&& rrHoge = 10; // OK

auto hogeFunc_l = [](std::basic_string<TCHAR>& rStr){};
auto hogeFunc_r = [](std::basic_string<TCHAR>&& rrStr){};
std::basic_string<TCHAR> hoge(_T("hoge"));
hogeFunc_l(hoge); // OK
hogeFunc_l(std::basic_string<TCHAR>(_T("hoge"))); // NG
hogeFunc_r(hoge); // NG
hogeFunc_r(std::basic_string<TCHAR>(_T("hoge"))); // OK

auto hogeFunc = [](std::basic_string<TCHAR>& rStr){};
auto hogeFunc = [](std::basic_string<TCHAR>&& rrStr){};
hogeFunc(hoge); // 左辺値参照
hogeFunc(std::basic_string<TCHAR>(_T("hoge"))); // 右辺値参照
hogeFunc(static_cast<std::basic_string<TCHAR>&&>(hoge)); // 右辺値参照（だがあまり好ましい書き方ではない）
hogeFunc(std::move(hoge)); // 右辺値参照（多分こっちのほうが好ましい）
```
何に有用かというと，以下の時に実体のコピーがされないことで，実行速度の改善が見込まれる．   
```cpp
auto hogeFunc = [](std::basic_string<TCHAR>&& rStr){};
std::basic_string<TCHAR> ho(_T("ho")), ge(_T("ge"));
std::basic_string<TCHAR> hoge(ho+ge);
// この上式では，一旦"ho+ge"の結果の参照型が返り，その後コピーコンストラクターが実行される．
// しかし，ムーヴコンストラクターが定義されていると，結果の参照型が直にムーヴコンストラクターへ渡される．
```
右辺値参照の定義に伴って，ムーヴコンストラクタとムーヴ代入演算子が新しく定義されている． 

もう一例  
```cpp
class CTestArray
{
public:
    CTestArray();
    CTestArray(const CTestArray&);
    CTestArray(CTestArray&&);
    virtual ~CTestArray();

    CTestArray& operator=(const CTestArray&);
    CTestArray& operator=(CTestArray&&);

private:
    unsigned int    m_dataNum;
    int*    m_pData;
};

CTestArray::CTestArray()
: m_dataNum(0)
, m_pData(nullptr)
{
    OutputDebugString(_T("default constructor\n"));
}

CTestArray::CTestArray(const CTestArray& crTeatsArray)
{
    this->m_dataNum = crTeatsArray.m_dataNum;
```

## override指定子
override指定子により，そのメソッドがoverrideかどうかを明示的にすることができる．   
```cpp
class CHoge1
{
    virtual void func1() const final {};
    virtual void func2() const {};
    void func3() const {};
};
class CHoge2 :public CHoge1
{
    // 派生先ではvirtalは必要ない
    void func1() const override {}; // NG finalメンバ関数はオーバーライドできない
    void func2() const override {}; // OK
    void func3() const override {}; // NG 仮想関数では無いので、オーバーライドできない
```

virtualルール

- 「派生クラスのポインターを基底クラスのポインターにキャストして使用するなら，基底クラスのデストラクターがvirtualでなくてはならない」 ≒ 「仮想メソッドを持つクラスの基底クラスのデストラクターはvirtualでなくてはならない」
- 暗黙的に作られるデストラクターはvirtualではないので，デストラクターが空の場合でもvirtualなデストラクタを明示的に定義しなくてならない
- 「vtableへのポインターの分だけインスタンスのサイズが増える」「virtual呼び出しはvtableを利用する分遅くなる」 ≒ 「プリモーフィズムを利用しないクラスでは不必要にvirtualをつけるべきではない」  
ただしここまでシビアでなければ，「常にデストラクターはvirtualにすべき」「継承される可能性のあるクラスのデストラクターはvirtualにすべき」でもよい

### 暗黙の定義
|暗黙的に宣言されるか→<br>↓手動で宣言したもの|デフォルトコンストラクター|デストラクター|コピーコンストラクター|	コピー代入演算子|ムーブコンストラクター|ムーブ代入演算子|
|---|:---:|:---:|:---:|:---:|:---:|:---:|
|宣言無し|○|○|○|○|○|○|
|その他のコンストラクター|x|○|○|○|○|○|
|デフォルトコンストラクター|\ |○|○|○|○|○|
|デストラクター|○|\ |○（※）|○（※）|x?|x?|
|コピーコンストラクター|x|○|\ |○（※）|x|x|
|コピー代入演算子|x?|○|○（※）|\ |x|x|
|ムーブコンストラクター|x|○|delete|delete|\ |x|
|ムーブ代入演算子|x?|○|delete|delete|x|\ |

第一列の宣言は，明示的なdefault宣言，明示的なdelete宣言，ユーザー定義を指す．  
○…暗黙的に宣言される．  
☓…暗黙的に宣言されない．  
delete…暗黙的にdelete宣言される．  
※…暗黙的に宣言されるが，非推奨である．（明示的に宣言すること）  
暗黙的に作られるデストラクターはvirtualではない  
以上のことから，通常のクラスにおいては，デフォルトコンストラクター（必要に応じてその他のコンストラクター）のみを定義し，その他は定義しないことが望ましい．

```cpp
    // /*virtual*/ ~CHoge() = default;  // virtual指定をするため（しかし，この型の変数をconstexprしたいためには，virtual指定しない方がいい）
    // CHoge& operator=(const CHoge& crHoge) = default;
```

## constexpr
定数式．constが実行時に評価されるのと異なり，`constexpr`はコンパイル時に評価される．用法は二つ．  
変数に対して`constexpr`をつけると，コンパイル時定数になる．但し，リテラル型の変数でないといけない．  
関数に対して`constexpr`をつけると，コンパイル時に評価されるconstexpr関数になる．但し，constexpr関数には厳しい制限がある．変数の宣言はできないし，return文は唯一しか書けない．  
また，constexpr宣言された関数からの戻り値をconstexprで受け取りたい場合には，その呼び出し引数にconstexprな値を渡さなければならない．  
メソッドに`constexpr`をつけると，暗黙的にconstメソッドになる（thisもconstexprな値でなければならないので，thisを書き換える事はできないという趣旨）．  
constexpr宣言されると，自動的にinline宣言されるので，分割ファイルでは使用できない．  
テンプレート関数に`constexpr`をつけるとややこしいので，つけない方がいい．  
結果がROM化できないと，constexprにはできない．  
```cpp
// NG
constexpr double absolute(double a, double b)
{
    double tmp = a + b; // 変数を取れない
    return abs(tmp); // 関数呼び出しが出来ない
}
//NG
constexpr double absolute(double a, double b)
{
    double tmp = a + b; // 変数を取れない
    if (tmp < 0.0) return -tmp; // return文を複数書けない
    else           return  tmp; // return文を複数書けない
}
//OK
constexpr double absolute(double a, double b)
{
    return (a+b)<0.0 ? -(a+b) : (a+b);
}
```

## 疑似乱数
非決定的な乱数生成器として`std::random_device`がある．

`std::random_device`をそのまま使用してもいいが，いったんエントロピープールを使い果たすと急激に性能が低下するため，通常は決定的な乱数生成器を使用する．  
ここで言う「決定的」とは、現在の値により次の値が一意に決まるという意味（同じシードを与えると同じ値を得ることになる）．擬似乱数とも呼ばれ、数学的に完全な乱数ではない．

戻り値は，`float` `double` `long double`．引数と戻り値は同じ方が望ましい．

### trunc
絶対値がより大きくない最も近い整数（zeroに向かって丸めた整数）を返す．  
戻り値は，`float` `double` `long double`．引数と戻り値は同じ方が望ましい．

### round
[l,ll]roound … lの場合は戻り値は`long`, llの場合は戻り値は`long long`．  
最近の整数（中間値の場合はzeroから離れる方向に丸めた整数）を返す． 

## 丸めモードを使用した丸め

### nearbyint
現在の丸めモードに従った最近の整数を返す．  
`std::nearbyint`と`std::rint`の唯一の違いは、 `std::nearbyint`が`FE_INEXACT`を発生させないこと．  

### rint
[l,ll]rint … lの場合は戻り値は`long`, llの場合は戻り値は`long long`．  
現在の丸めモードに従った最近の整数を返す．  

### fegetround/fesetround
浮動小数点の丸め方向を取得/設定する．   
| | |
|---|---|
|FE_DOWNWARD|負の無限大に向かった丸め（floorと同様）|
|FE_UPWARD|正の無限大に向かった丸め（ceilと同様）|
|FE_TOWARDZERO|ゼロに向かった丸め（truncと同様）|
|FE_TONEAREST|表現可能な最も近い値に向かった丸め（roundとは異なり，中間値の場合は偶数に丸める）|

### Z 8401：2019
- 2-b-1に「与えられた数値に等しく近い，二つの隣り合う整数倍がある場合には，丸めた数値として丸めの幅の偶数倍の方を選ぶ」とあるが，これは丸めモード`FE_TONEAREST`と同等である．
- 2-b-2に「与えられた数値に等しく近い，二つの隣り合う整数倍がある場合には，丸めた数値として大きい整数倍の方を選ぶ．ただし，負の数値を対象とする場合は，その絶対値に適用する」とあるが，これは`round`と同等である．

## dangling
綺麗な顔してるだろ．うそみたいだろ．死んでるんだぜ．これで……   
```cpp
std::vector<int> p{3,1,4,1,5,9,2,6,5,3,5};
std::vector<int> e{2,7,1,8,2,8,1,8,2,8};
auto mm = std::minmax(p.size(), e.size());
std::cout << "min:" << mm.first << " max:" << mm.second << std::endl;
```
mmの型は`std::pair<const size_t&,const size_t&>`で実体を持たない．つまりsizeの結果は一時変数であり，その時点で破棄されており，danglingとなる．  
これを回避するには，戻り値を`auto`ではなく`std::pair<size_t,size_t>`と実体で受け取らなければならない．しかも，たまたまうまく動くこともあるから厄介．
